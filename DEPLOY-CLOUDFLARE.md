# Публикация сайта на Cloudflare Pages

Сайт полностью статический (HTML + JS + CSS, данные в `data/*.js`), поэтому переносится
без изменений. Специальной поддержки Netlify в проекте нет — `.netlify` можно игнорировать.

Есть два способа: **простой (через панель)** и **скриптом одна кнопка**.

---

## Важно: не публикуйте служебные файлы

В корне проекта лежит `opencode.json`, в котором записан ваш **API-ключ**. Если залить папку
целиком, этот файл станет доступен по адресу `https://ваш-сайт/opencode.json`.

Поэтому перед публикацией собирается чистая папка `.deploy` (скрипт `tools/build-deploy.js`),
куда `opencode.json`, `opencode.txt`, `.netlify` и прочая служебка **не попадают**.

---

## Способ 1. Скриптом (рекомендуется)

Понадобится установленный **Node.js** (у вас уже есть).

1. Дважды кликните **`deploy-cloudflare.bat`** в корне проекта.
2. При первом запуске откроется браузер — **войдите в аккаунт Cloudflare** (или создайте бесплатный).
3. Скрипт соберёт `.deploy` и загрузит сайт. Если проект ещё не создан, wrangler спросит
   имя — согласитесь создать (`azstec`).
4. Готово. Адрес будет вида **`https://azstec.pages.dev`**.

Повторная публикация после правок — снова запустить `deploy-cloudflare.bat`.

---

## Способ 2. Перетаскиванием (без установки чего-либо)

1. Запустите сборку: в терминале в корне проекта выполните
   ```
   node tools/build-deploy.js
   ```
   Появится папка `.deploy`.
2. Зайдите на https://dash.cloudflare.com → **Workers & Pages** → **Create** → **Pages** →
   **Upload assets**.
3. Укажите название проекта (например `azstec`) и **перетащите папку `.deploy`** в окно загрузки.
4. Нажмите **Deploy site**.

> ⚠️ Загружайте содержимое `.deploy`, а **не** корень проекта — иначе утечёт `opencode.json`.

## Подключение домена azstec.ru

Домен подключается бесплатно в обоих способах:

1. В панели Cloudflare: **Workers & Pages → ваш проект → Custom domains → Set up a domain**.
2. Введите `azstec.ru` (и при желании `www.azstec.ru`).
3. Cloudflare покажет, какие DNS-записи нужно прописать.
   - Если домен **уже переведён на Cloudflare** (NS-серверы Cloudflare) — записи добавятся сами.
   - Если домен у другого регистратора/хостинга — добавьте предложенные записи (обычно `CNAME`
     на `<проект>.pages.dev` либо `A`/`AAAA` на IP Cloudflare) в панели управления домена.
4. Дождитесь проверки (обычно несколько минут). HTTPS-сертификат выдаётся автоматически.

## Что происходит с редактором (admin.html)

Редактор работает на стороне браузера (права и вход — `data/users.js`, новости пишутся в
localStorage). Чтобы опубликованные через редактор материалы появились на сайте:

1. В редакторе нажмите **«Скачать data/news.js»** (и при необходимости **«Скачать data/users.js»**).
2. Положите скачанные файлы в папку **`data/`**, заменив существующие.
3. Перезапустите публикацию (`deploy-cloudflare.bat` или сборка + загрузка).

Браузерный вход защищает от случайных правок и разграничивает доступ сотрудников, но не является
полноценной серверной авторизацией. Когда понадобится настоящий общий вход — на Cloudflare это
удобно сделать через **Workers** (бесплатный тариф есть) на том же аккаунте.

## Полезные команды

| Действие | Команда |
|---|---|
| Собрать папку для публикации | `node tools/build-deploy.js` |
| Войти в Cloudflare | `npx wrangler login` |
| Опубликовать | `npx wrangler pages deploy .deploy --project-name=azstec --branch=main` |
| Посмотреть список проектов | `npx wrangler pages project list` |
