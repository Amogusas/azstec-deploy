# Публикация сайта на GitHub Pages

GitHub Pages — тоже **бесплатно** (для публичных репозиториев), без карты, работает в РФ
стабильнее Cloudflare. Сайт статический, специальной сборки не требует; в проекте уже есть
готовая автоматизация (`.github/workflows/deploy-pages.yml`), которая сама публикует сайт
при каждом обновлении.

---

## ⚠️ Сначала — про безопасность

В корне лежит `opencode.json` с вашим **API-ключом**. В файле `.gitignore` он уже исключён,
поэтому на GitHub он **не попадёт**. Пожалуйста, не удаляйте эти строки из `.gitignore`:

```
opencode.json
opencode.txt
```

После публикации **обязательно проверьте**, что файла нет в репозитории:
зайдите на `https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ` и поищите `opencode.json`.
Если он там оказался — удалите файл и смените API-ключ.

---

## Способ А. Через GitHub Desktop (рекомендую, без командной строки)

Git в системе не установлен, поэтому проще всего через приложение GitHub Desktop.

1. Установите **GitHub Desktop**: https://desktop.github.com и войдите в свой аккаунт GitHub
   (если аккаунта нет — создайте бесплатно).
2. В меню: **File → Add local repository…**
3. Укажите папку **`C:\Users\user\azstec-deploy`**.
4. Появится сообщение, что это не git-репозиторий — нажмите **«create a repository»** →
   подтвердите создание.
5. В левом списке появятся файлы на коммит. **Проверьте, что среди них НЕТ `opencode.json`.**
6. Внизу слева введите описание (например `Сайт АЗС Технологии`) и нажмите **Commit to main**.
7. Сверху нажмите **Publish repository**. **Снимите галочку «Keep this code private»**
   (на бесплатном плане Pages работает только для публичных репозиториев) → **Publish**.
8. Откройте репозиторий в браузере → **Settings → Pages** → в разделе *Build and deployment*
   выберите **Source: GitHub Actions**.
9. Пуш идёт автоматически: откройте вкладку **Actions** репозитория и дождитесь зелёной галочки.
10. Адрес сайта будет: **`https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`**

После любых правок: в GitHub Desktop снова Commit → Push, и сайт обновится сам.

## Способ Б. Через командную строку (если установите Git)

1. Установите Git: https://git-scm.com/download/win
2. Создайте **пустой** репозиторий на GitHub (без README).
3. В терминале в папке проекта выполните (замените ссылку на свой репозиторий):

```
git init
git add .
git commit -m "Сайт АЗС Технологии"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

Дальше — пункты 8–10 из способа А (Settings → Pages → Source: GitHub Actions).

## Подключение домена azstec.ru

1. В репозитории: **Settings → Pages → Custom domain** → введите `azstec.ru` → Save.
   GitHub создаст файл `CNAME`.
2. У регистратора домена (например, Reg.ru) пропишите DNS-записи — GitHub покажет нужные.
   Обычно это четыре **A**-записи на IP GitHub Pages и **CNAME** для `www`:
   ```
   185.199.108.153
   185.199.109.153
   185.199.110.153
   185.199.111.153
   ```
   (точные значения всегда берите на странице GitHub → Pages, они могут меняться)
3. Дождитесь проверки DNS (от нескольких минут до нескольких часов).
4. Включите галочку **Enforce HTTPS**.

## Что делать с редактором (admin.html)

Как и раньше: после правок в редакторе нажмите **«Скачать data/news.js»** (и при
необходимости **«Скачать data/users.js»**), положите файлы в папку `data/` проекта и
сделайте Commit → Push в GitHub Desktop. Сайт обновится автоматически.

## Частые вопросы

**Сайт не открывается — что проверить?**
- В **Actions** последний запуск должен быть зелёным.
- В **Settings → Pages** источник должен быть **GitHub Actions**.
- Подождите 1–2 минуты после первого деплоя.

**Почему нужен публичный репозиторий?**
GitHub Pages для приватных репозиториев требует платный план Pro. Публичный — бесплатно.
Секретов в нём нет (`opencode.json` исключён через `.gitignore`).

**Лимиты бесплатного тарифа:** ~1 ГБ на сайт, ~100 ГБ трафика в месяц, 10 сборок в час —
для такого сайта (44 МБ) с запасом.

**Что за файлы `_headers` и `deploy-cloudflare.bat`?**
Остались от варианта с Cloudflare. На GitHub Pages они безвредны, можно не удалять.
